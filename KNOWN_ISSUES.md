# Known Issues and Technical Debt

Snapshot at handoff. Update as items are resolved.

---

## AI engine limitations

1. **ply24 Lich shuffle (regression fixture).** Root royal-shuffle penalty
   in `search.ts` (`isRoyalShuffleAtRoot`) doesn't fire on long-range
   lateral back-rank shuffles because it relies on `revisitsPriorSquare`
   and a 24-ply lookback. Proposed fix: broaden to "any quiet lateral
   royal step with a prior same-royal move anywhere in history and no
   rank change". Not yet implemented.

2. **ply29 Dragon donation (regression fixture).** Safety gate's donation
   penalty (×3) is overwhelmed by `evaluate.ts`'s threat/king-pressure
   terms when `oppGain ≈ moverValue`. Proposed fix: hard-reject in
   `runSafetyGate` when `oppGain >= moverValue * 0.8`, with fallback to
   the smallest-`oppGain` candidate (not highest `adjusted`). Not yet
   implemented — held pending broader regression testing.

3. **Depth-1 starvation risk on huge variants.** Iterative deepening can
   time out before depth 1 finishes on extremely large boards or huge
   piece sets. A "always complete depth 1" guarantee exists but root
   candidate ordering may still be incomplete.

4. **Custom piece evaluation is generic.** `evaluate.ts` uses a
   centralization + mobility heuristic for `u:*` pieces and has no
   piece-square tables for them. High-value custom pieces can be mis-
   evaluated.

5. **Qsearch is captures-only.** No quiet-threat extension. Pieces that
   walk into pin/skewer setups one ply beyond horizon are not seen.

6. **Playbook invalidation is coarse.** Any edit to a variant's piece set
   invalidates all prior `ai_playbook_stats` rows for that variant.

## Performance concerns

- **TT replacement** is depth-preferred only; no aging. On long sessions
  the TT can fill with stale deep entries from earlier games of the same
  variant.
- **Zobrist key cache** is reset on variant salt change, but during a
  single session with many variant switches this thrashes.
- **Realtime move sync** uses Supabase Realtime channels with no
  reconnection backoff beyond the default — long-disconnect users may
  miss moves until manual refresh.

---

## Architecture concerns

- **No CI / test runner.** `benchmark.ts` and `realGameBenchmark.ts` are
  scripts, not vitest cases. Regressions are caught manually.
- **Lovable-owned files.** `src/integrations/supabase/{client,client.server,types,auth-middleware,auth-attacher}.ts`,
  `supabase/config.toml`, and `.env` are auto-managed by Lovable's
  integration. Editing them from outside Lovable will be overwritten on
  next sync. If we leave Lovable entirely, these become hand-maintained.
- **Generated route tree.** `src/routeTree.gen.ts` is auto-generated by
  the TanStack Router Vite plugin. Editor changes will be overwritten.
- **Dual "AI" naming.** "AI" can mean either the in-browser game engine
  or the Lovable AI Gateway LLM helpers. These are completely separate
  systems — keep them clearly distinguished in code and PR descriptions.
- **No formal error tracking** beyond `src/lib/error-capture.ts` ad-hoc
  logging. Consider Sentry or equivalent before scaling.
- **PWA service worker** (`public/push-sw.js`) is hand-rolled and doesn't
  participate in Vite's asset hashing.
